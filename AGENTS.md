# PDSH Agent Guide

This is the project constitution for PDSH; root `CLAUDE.md` links here. Module `CLAUDE.md` files map the TypeScript source and tests. Private research evidence belongs in the private `daftAI-project-docs/pdsh/` repository.

## Project

Public code repository: `https://github.com/daftAI2026/PDSH` (uppercase repository name). The npm package identifier remains lowercase `@daftai/pdsh`; it is not published to npm.

PDSH means Private DeepSeek Harness; public display names are `DSH 私密模式` / `DSH Private Mode`. The brand does not imply that isolation is implemented.

PDSH is the DeepSeek Harness Desktop adaptation of InCodex's presentation and eventual incognito experience. The official Harness app is the host; PDSH is an out-of-tree Cordis plugin bundle. The **0.2.1 release** replaces 0.2.0's OS capture route with renderer-local whole-viewport DOM rasterization while retaining the editor and makes the update affordance a thinner, semantic-success-color arrow. Source labels stay beside the nickname; the nickname row owns symmetric bottom-area padding. Capture and workbench failures are distinct, and generic failure must not infer Screen Recording denial. Full installed Desktop workbench acceptance remains outstanding and must not be claimed from the tag alone. PDSH does not isolate sessions, open another DeepSeek instance, transfer credentials, erase history, or provide a privacy guarantee.

The InCodex repository at `../incodex` is the reference for product behavior and safety invariants, not a template to copy wholesale. Its `AGENTS.md` was used as the starting convention for this guide; Codex-specific commands and assumptions do not apply here.

## Product direction

- Keep the official DeepSeek Harness app and normal launch path. Prefer its documented plugin interfaces; do not patch or re-sign the app for the standard PDSH installation.
- Stay in the existing window. A screenshot workbench is now in scope; no CLI product, second app instance or session/burn module is needed.
- UI language follows Harness Settings → General → Language through `ctx.locale`; metadata comes from exported `locale/*.json`. Never translate the user's configured nickname or add a second language store.
- Use the official Plugins page for settings and the Host settings document for persistence. Switches and avatar source actions persist immediately; nickname owns a local draft committed by check/Enter; avatar/source always persist atomically; do not persist credentials or real account data.
- Trace every visual rule to the upstream file, selector and variable in `style-sources.json`. Use semantic `--dsw-*` colors/radii, native React primitives, and runtime-computed native stroke geometry. No numeric color/geometry fallback or copied CSS Modules hash.
- The avatar-source control has a visible label. React settings and update controls use Host `Tooltip` with the Desktop icon parameters; the DOM-only sidebar/workbench controls use one disposable adapter with the same delay, placement, gap and theme tokens. Do not fall back to browser `title` bubbles.
- Identity replacement is only a visual overlay (or preserve the native account avatar when explicitly selected) on a uniquely recognized rc.2 sidebar launcher. Keep its native button, account nodes, menus and sign-in/out semantics. Do not mask signed-out More, full settings, account data, model payloads or logs. Unknown/multiple identities skip replacement; this is not a fail-closed privacy system.
- The hat entry toggles accepted Host `maskTitles` directly, without a menu or settings navigation. The exact search-icon-adjacent location has no supported child slot; do not claim it does. Settings stay in the official Plugins page. Retire legacy `frames`; do not reinterpret old values as title masking.
- Current unreleased source retires DOM rasterization. The camera requires a versioned, current-page PNG bridge from Electron Main and opens the editor only after receiving frozen native pixels. `dshDesktop.pageCapture` is a proposed integration contract, not an existing DSH API; the installed rc.2 Host does not expose it. The current candidate can instead load its bundled Main bridge through a short-lived inspector bootstrap when the capture component is enabled and its camera is clicked, using the normal Desktop launch path. This is not an official Host API; its exact installed capture acceptance remains outstanding. No DOM fallback, OS capture, CDP startup flag requirement, native helper, ASAR patch or re-signing is allowed. Native macOS chrome is out of scope; WebContents pixels do not automatically include separate WebContentsView or AppKit vibrancy behind transparent page regions. Exact Host page-pixel coverage acceptance is required. The user approved an explicitly simulated macOS sidebar material for edit/export: material.ts uses the measured macOS 27.0.1 blur/saturation/fill/tone recipe over the chosen editor background, below unchanged PNG pixels. This approximation is not native vibrancy capture, must not replace page-pixel coverage proof, and never samples the real desktop or composes multiple live frames. Screenshot pixels never become settings, logs or network payloads.
- The workbench UI inherits DSH semantic `--dsw-*` theme, typography, radius, shadow and motion tokens. Editor-produced gradients, wallpaper pixels, color spectrum and transparency checkerboard are content, not theme chrome. No inherited Codex theme classes or numeric fallback theme colors; trace DSH tokens to `style-sources.json`.
- Prove an isolated DSH home **and** Electron user-data root before claiming a private window. The app has a single-instance lock; a second independent instance is a hypothesis until tested against the exact build.
- Never modify or delete the user's primary `~/.dsh` profile, sessions, credentials, or Chromium data while prototyping isolation.
- Do not claim forensic privacy. Define which histories, requests, tool outputs, logs, and files the privacy contract covers, then test those paths separately.

## Reuse boundary

Preserve the behavior and tested invariants from InCodex: private session directories, exclusive creation, symlink and path-escape rejection, owner/PID identity checks, uncertain-state retention, close-time cleanup, icon assets, localized copy, and the relevant regression tests. Reuse one Host-language implementation after the Harness lifecycle is known; do not port both Rust and Electron copies by default.

Do **not** import InCodex's `CODEX_HOME`, Codex `auth.json`/`config.toml`, ChatGPT bundle paths, ASAR patching/signing, Codex DOM selectors, IPC channels, or profile-masking assumptions. DeepSeek account state and configuration require their own explicit, reviewed adapter.

- `package.json`/`pnpm-lock.yaml`: bundle manifest and reproducible dependencies; `cordis.patch.yml`: the sole Cordis insertion layer.
- `build.ts`/`tsconfig.json`: TypeScript-to-Host build and source typecheck; runtime JavaScript is generated, not separately authored.
- `plugin-icon.svg`: generated manifest artwork; `THIRD_PARTY_NOTICES.md` and `LICENSE`: distribution notices.
- `AGENTS.md`/root `CLAUDE.md`: one project constitution; module `CLAUDE.md` files are navigational maps, not competing policy sources.
- `output/` and `node_modules/` are generated/ignored. Internal component files and their Client manifests ship under `components/` and as two bundled package roots. Only the two build-owned `node_modules/@daftai/pdsh-{titles,capture}` self-links are tracked for Git distribution; third-party node_modules contents remain forbidden. Generated runtime JavaScript and the two build-owned component self-links are committed for Git/local installs; hand-authored behavior stays in TypeScript.

## Component composition

- The user confirmed three independently toggleable components in the official Bundle detail: identity (avatar + nickname), sidebar-title masking, and capture. The patch retains legacy bare `@daftai/pdsh` / `pdsh` for identity preferences and uses bundled package names `@daftai/pdsh-titles` / `pdsh-titles` and `@daftai/pdsh-capture` / `pdsh-capture`. Each package exposes its own Host, Client, manifest and locale resources; the official Bundle dependency closure supplies profile resolution so Client and metadata discovery read the same component as Loader; relative file entries bypass metadata and are not the distribution contract. Internal manifest names remain stable Client table IDs and are real bundled dependencies, not separately managed profile installations. Installed bridge acceptance remains outstanding; component names and lifecycle evidence do not prove pixel delivery.
- Treat the three components as independent behavior owners, not three copied implementations or mutually dependent switches. Capture imports `recognizedSidebarTitles` from the title adapter and `recognizeSidebarIdentity` from the identity adapter. Permanent and capture-only title markers consume the same gray-bar CSS rule; capture restores only attributes it still owns and never toggles the accepted `maskTitles` preference. Disabling daily masking must restore native titles without preventing capture-only masking. Disabling identity must restore native account nodes without deleting the accepted alias preferences. Capture disable must cancel its work, restore temporary markers and release its editor/bridge resources; bridge loss must not disable identity/title behavior.
- The bridge is non-visual infrastructure with its own connection, request and disposer boundary, distributed inside the Bundle and consumed through `PageCapturePort`. It is not a fourth user presentation feature, nor a reason for the identity/title runtime to depend on capture. A shared recognizer/style library remains usable when the runtime that paints permanent masks is disabled; use Cordis service injection only for a genuine live provider dependency, not merely for sharing pure code. The successful original-DSH plugin-started Main capture experiment proves that nonstandard route, not formal automatic startup/unload or renderer-to-editor delivery of the packaged product.

- Current unreleased settings place the avatar-source label inside the right-aligned source action group. Its visible gap before the first outlined button matches the text gap between the two ghost source actions, using the live Host field gap and Button padding, not a numeric spacer. The 0.2.1 nickname-adjacent layout below records the prior release.
- Capture and workbench feedback uses the official React `Toast` and warning/success glyphs. The Host owns its style, portal and default hold/fade lifetime; do not keep a custom persistent bottom-corner notice or duplicate notification timers. Each show gets a new key, stale completion cannot dismiss a newer notice, retake clears the owned notice before pixels are acquired, and Bundle unload unmounts its React root.

- Distinguish three boundaries: an installable bundle, a Cordis runtime plugin entry, and a React component. The plugin page's component count describes runtime entries, not the number of React components or features in the bundle.
- Keep one installable Bundle containing the three independently enabled runtime entries. Preserve the existing `pdsh` configuration identity or perform a revision-fenced migration through the official settings owner; never silently discard nickname/avatar/source/masking preferences or introduce competing active stores. `src/host/index.ts` currently owns the legacy configuration contract, `src/shared/model.ts` owns pure validation, `src/client/client-entry.tsx` is a thin role entry; `component-runtime.tsx` owns assembly and shared resource lifetime, `settings-card.tsx` owns field-local editing and immediate mutations, `presentation.ts` owns the account DOM adapter, `sidebar-redaction.ts` owns title markers, and `title-toggle.ts` owns the hat mutation. No message outlines remain.
- `src/client/update-badge.tsx` uses the supported `plugins.detail.badge` slot immediately after the Host version tag; only the own Bundle starts a network probe when its detail page mounts. No update card, manual check button or background polling remains. `updater.ts` owns check/install state and `update-source.ts` is its only public GitHub HTTP boundary. Installation requires a second explicit action, pins a SHA through the official Host manager, never auto-restarts, and states source migration on expansion. Do not add a second installer or write update state into preferences.
- `src/client/capture/controller.ts` is the camera effect boundary; `src/client/capture/viewport.ts` alone validates and decodes frozen current-page PNG pixels and `src/client/capture/editor.ts` alone coordinates editing. The camera sits right of the hat, inherits native search geometry and whole-SVG opacity, hides during search expansion and disposes with the Bundle. Only non-sensitive workbench preferences are stored locally; no screenshot pixels in configuration or logs.
- Split a UI component when it owns meaningful rendering or interaction; split a controller when it owns an independent effect and disposer. Do not create a Cordis plugin per button, a second settings store, or speculative service/provider packages. Use separate runtime entries only for independently enabled capabilities or actual service dependencies.
- The search-adjacent entry is a version-specific DOM adapter, not a supported child slot. It remains separate from account presentation and toggles one Host `maskTitles` path with pending/read-only guards. Preserve native search, copy only its live style class/geometry, place enabled hat/camera immediately left of search using owned auto spacing on the first active control and a visibility-scoped adjacent slot margin rule, hide added controls during expanded search, and skip unknown/ambiguous structures. Never replace/copy the full browser merely to add buttons, or label a display-only entry as an active private session.
- Current unreleased source resolves native sidebar SVG stroke through its live viewBox/display geometry instead of the artwork default. `native-icon.ts` owns that coordinate conversion; `native-style-probe.ts` owns one non-painted, layout-measurable Host control probe, reacts to theme/DOM/resource/resize changes, and restores its CSS variables and observers on unload. Host theme tokens remain direct CSS references; missing metrics have no numeric fallback. Workbench icons, Button/Switch and DOM Tooltip consume the same live measurements. Editor layout ratios and exported content remain PDSH/user-owned, not imaginary Host settings.
- Every future entry must retain native search behavior, trace its visual dependencies to upstream providers, and dispose only its own nodes/registrations. Test sidebar fold state, search expansion, remount and bundle disable before claiming Desktop compatibility.

## Workflow and safety

1. For plugin mechanics, read the [official first-plugin guide](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/) and [bundle/install guide](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish) for the target version. `dsh plugin add` installs a bundle; it is not a project generator.
2. Develop against a disposable profile first. Do not install this scaffold into the user's live `desktop` profile merely to smoke-test packaging.
3. Git pushes do not update installed packages. Use the official manager with a new reviewed Git SHA, preserve configuration, then restart after replacing an existing package. Never bypass Electron-exclusive Desktop management through the external CLI.
4. Start behavior changes with a failing contract test; then implement and verify the exact Desktop build. A successful package archive does not prove a working UI contribution or isolation.
5. Keep `apply` lifecycle-managed. When adding subscriptions, windows, timers, or IPC, register disposal and test unload/restore. Fail closed on ambiguous ownership before cleanup.
6. Treat each external plugin as trusted executable code; inspect the bundle and explicit dependencies before installing. Never silently copy credentials into a temporary profile.
7. Ordinary private research and decisions belong in the private docs repo, published with its `private-docs-publish` skill and repository write lock. Do not place private user data here.

## Desktop debugging

Prefer an already enabled loopback CDP connection. Do not activate or steal the user's foreground window; do not silently restart Desktop just to enable CDP. A Host HTTP listener is not a CDP endpoint. If CUA is unavailable and CDP is not enabled, background inspection may establish the remaining gap, but cannot substitute for real Desktop verification.

Use the installed build-macos-apps `swiftui-patterns` skill as a desktop-interaction reference for editing, cancellation, focus and discoverability, not as a framework dependency. Harness owns the settings surface, controls, persistence and commands; do not add a SwiftUI window, AppStorage, a second settings store or global shortcuts merely to mimic native macOS.

## Current unreleased capture direction

No window ID, URL, rectangle or executable code crosses this API. Main must bind the caller to the owned primary main frame and document generation, retain a single in-flight native capture through settlement, check native representation/DPR and pixel/byte budgets, and reject lifecycle changes. The following 0.2.1 section records the already released legacy route, not the current source implementation.

## Installed composition regression

The first local 0.3.0 candidate failed before child `apply`: its patch referenced two bare packages available only inside the Bundle, while Loader resolved from the profile. The earlier consumer probe used Bundle-local resolution and therefore was an invalid Host-loading oracle. This candidate uses patch-relative internal entries and adds profile-root resolution/Client manifest checks; source tests alone still do not prove installed startup. Keep the failing candidate disabled through the official manager until replacement is verified.

A separate actual Desktop web-boot fatal report showed `pdsh-capture` pending on the nonexistent `connection.rpc` service. The official Connection provides only `connection`; `rpc` is a member of its handle. Client inject now depends on `connection` only. A real Cordis registry regression tests generated dependency declarations and withdrawal, unlike the older direct-apply DOM fixtures. Both regression guards must pass before installed acceptance is retried.

The Main bootstrap identity probe must keep `comm` as the final macOS ps column: `comm=,lstart=` truncates the executable to 16 characters even with `-ww`, causing false identity rejection. The probe now parses `lstart=,comm=` into the full path plus start time; a read-only real-process regression covers the platform behavior. Never relax the identity check to match a truncated path.

Path-based title migration compares canonical local filesystem identity, not raw file-URL spelling: pnpm links are preserved in patch anchoring while Node ESM canonicalizes import.meta.url. The profile model test must anchor through the installation symlink and invoke the generated migration, not bypass it through the source path.

The capture component enable switch now owns bridge startup, lazily on the first camera request; no secondary `allowMainBridge` settings gate or constant risk banner remains. Legacy consent values do not disable capture. Bootstrap still refuses an occupied Main inspector port before signalling, never takes over another debugger, and reports port-busy/cleanup-unconfirmed separately. Capture settings own accepted `saveDirectory`, `saveFormat` (PNG/JPEG/WebP) and Kiri-inspired basename tokens (`{date}`, `{time}`, `{title}`, `{width}`, `{height}`). Directory selection uses the official DSH native picker; it grants no new plugin-wide file permission. The bundled Main save port presents a bound native Save dialog initially at the chosen directory, writes only the user-confirmed target, and returns `saved` only after write completion. Cancellation/navigation/unload before confirmation rejects writing. Export bytes and paths pass only through the bound Main-frame receiver, never HTTP or logs. Capture time/title freeze per shot; dimensions describe the final export. Settings reuse existing nickname detail rows, Input/Button and Tooltip, without permanent explanatory paragraphs. Clipboard remains PNG; JPEG flattens transparency to white. A formal capture-only Host port without a save port disables directory selection; its download handoff retains the editor and is not disk success. Main bootstrap still has the unresolved default-inspector port dependency; unit tests do not close installed capture/export release gates.

## Capture lifecycle state fences

Connection lifetime and page request ownership are separate. A new document owner retires the old session and waits for the retirement barrier before opening; it re-checks component activity and Main-generation quarantine after that wait. Confirmed closed failures may retry on the next click. Inspector-close-unknown and control-release-unknown are separate sticky states, not rejected Promises or renderer preferences. Host memory retains the guard across component disable/re-enable or package reload for the same Main identity; reading identity unsuccessfully cannot clear it. A normal DSH restart changes that identity. No owner switch, release, repeated click or settings write clears uncertain state. Unit tests cover both late unknown startup during an owner handoff and control disposal failure; actual Main startup/cleanup acceptance is still outstanding.

Save confirmation is human-controlled: no fixed RPC deadline pretends the native Save dialog has closed. Electron 44 has no SaveDialog AbortSignal; unload/cancel rejects committing bytes, but the system-owned sheet may remain until the user dismisses it. The Main save writer uses a same-directory exclusive 0600 temporary file, sync/close, lifecycle fence, then atomic rename; failed writes do not truncate the old target. PNG/JPEG use Electron nativeImage validation; WebP from the bound Canvas encoder uses explicit static RIFF/VP8/VP8L/VP8X envelope/dimension budgets, not an unsupported nativeImage decoder or a claim of general bitstream validation.

## Current export choices and startup boundary

The candidate has independent `saveBehavior` (`ask` / `direct`) and `saveDirectory`. Host initializes the directory to the local home Downloads path, not a claim to discover macOS/browser download preferences. The full accepted path is visible. Legacy empty directory and the exact legacy default `DSH {date} at {time}` are corrected through the official revision fence; other directories/templates remain unchanged. New defaults use `PDSH-screenshot-{date}-{time}`. Ask opens the bound Save dialog initially at that directory; direct saves without a dialog and uses exclusive automatic numbering, never silently overwriting. Both commit paths re-check document/lifecycle ownership. A capture-only provider must not claim direct directory saving without a save provider. The capture header's first field has no separator; subsequent fields retain shared native separators.

The bootstrap's Node-default 9229 is not a user-chosen product endpoint. SIGUSR1 wakes the existing Main Agent and cannot carry a new port; Host `process.debugPort` affects only Host. The dynamic owned socket after module injection does not solve that first Main entry. The rc.2 Main/Host IPC has no module-load/capture action and rejects unknown events. Do not fake dynamic bootstrap by scanning another free port, sending an invented IPC action or closing another program. Ordinary installed native capture remains a release blocker until a supported Main provider/hook or explicitly changed startup contract is verified.

Main module discovery is package-local: `fileURLToPath(new URL('./main.cjs', import.meta.url))` resolves against the installed generated capture Host, not a development folder, working directory or guessed DSH application root. Node owns OS-specific file-URL conversion. `tmpdir()` only supplies the root for per-connection exclusive socket directories; it never locates the shipped Main module. POSIX, Windows drive-letter and UNC conversion contracts are tested; those tests do not claim Windows bootstrap support, since the current experimental inspector route is macOS-only.

Both bridge endpoints now validate the same OS-provided temporary root. Main accepts canonical root aliases but requires an absolute normalized socket path, the fixed socket basename, an exclusively named real directory owned by its uid with mode 0700, and applies mode 0600 to the socket. It must not reintroduce a literal `/tmp` regex while Host uses `tmpdir()`. Real Unix-socket handshake tests prove this transport boundary, not the missing original-DSH Main loader entry. Extra relaunches on capture or every normal launch are not an accepted default product route; official installation restart-required only means replacement modules load on the next start and supplies no Main startup-argument API.
