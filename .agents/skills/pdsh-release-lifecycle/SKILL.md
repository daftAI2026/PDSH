# PDSH RC 与正式版生命周期

先回答两个问题：本次在验哪份代码？本次允许哪些动作？
版本号是标签，实际字节与运行结果才是证据。

## 入口与授权

先读 [根指南](../../../AGENTS.md) 和 [发布合同](../../../PUBLISHING.md)。
再读 `package.json`，以脚本定义为准。
本 skill 不保存版本表、候选进度或发布授权。
历史原话与结果只在私人文档查阅。
本项目默认只推 main 与稳定 tag，不创建 Release。
更新入口读 tags API，再按固定 SHA 安装。
“发版”不等于创建 GitHub Release 的单独授权。

- 只检查进度：只读，不构建、安装或发布。
- 制作或验证 RC：按需读 [RC 流程](references/rc.md)。
- 正式发布：按需读 [稳定发布流程](references/stable.md)。
- 接手续做：先核对旧回执，再选择上述流程。
- 只改公开文档：执行双语同步节，不构建 RC 或打 tag。

源码修改、候选构建、实机安装、重启、公开发布和私人发布分别核对授权。
已有本次明确授权时继续，不重复询问。
缺少授权时停在对应动作之前。
历史例外不授权下一版。
新发现的代码缺陷须披露，并重核本次发布决定。
明确授权的修复 tag 验证按本次范围执行，不冒充全兼容。
子代理型号、职责与总控边界遵守根指南。

## 冻结基线，不混用四种身份

记录分支、HEAD、工作树和本任务路径。
辨明陌生修改的所有权，不 stash、reset 或 clean。

| 身份 | 必须核对的事实 |
| --- | --- |
| 源码 | 稳定 manifest、Git SHA；脏树另记源码摘要 |
| 候选 | 包名、Config 根 ID、候选版本、归档摘要 |
| 宿主 | 精确构建、官方 Manager/Loader 与 PNPM 来源 |
| 实机 | 磁盘安装件、accepted 配置与实际 Host/Client |

RC 编号不是稳定版本，PDSH 版本不是宿主版本。
磁盘 manifest 不证明运行代码已经换载。
`setBundleEnabled` 不证明新代码生效。
Git push 不会更新已安装包。
不知道的身份明确记为未知，不推断 ACTIVE。
界面点击返回后，回读当前身份和目标后置状态。
目标过期、读回矛盾或结果未知时停止，不盲目重试。

## 同一安装件，独立验收门

每份结果绑定源码 SHA 或脏树摘要及归档摘要。
候选字节改变后，旧结果不能归给新安装件。
纯文档改动可复用未变运行字节的证据，须证明摘要相同。
不能只因版本号相同或“改得很小”就复用。

| 门 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 源码与合同 | 当前实现、类型和断言 | 真实安装或像素 |
| 构建与 tgz | 成员、字节、版本、原生格式与权限 | 业务实际载入 |
| 隔离 Host | 官方安装、实际业务版本与生命周期 | live Desktop |
| Desktop | 当前入口、主题、切换、焦点与状态 | 原生最终像素 |
| 原生链路 | 取像、预览/导出对位、复制、保存与取消 | 其他平台 |
| 恢复与升级 | 实际 RC 卸载、稳定恢复或正式升级 | 同版本重装之外的升级 |

设置持久化、媒体仓持久化和实际 Desktop 重启分别验收。
浏览器重载不证明 Desktop 重启持久化。
假 codec、picker、Canvas 或 transport 不证明真实链路。
Windows 编译和 PE 验证不证明 Windows 实机。
Windows 源码未变时，可绑定既有构建 SHA 和当前 EXE 摘要。
不得把历史 CI 写成当前提交的新 CI 成功。

## 防止“只注册成功”的假绿

读取 `verify-host.ts` 的 L3 与参数，再运行现有入口。
只使用全新、自有的 OS 临时 profile。
核对精确宿主和官方 PNPM 的来源与版本。
不复制凭据，不改 resolver 或 exotic-subdependency 策略。
官方 Manager、Loader 和 Settings 的结果不得伪造。

首次载入与重新启用均调用实际服务的 `implementationVersion()`。
把返回值与被装 manifest 比较，并绑定安装字节。
只注册 service/descriptors、核文件摘要或看 ACTIVE 都不够。
纯版本检查不取像、不下载媒体，也不启动原生助手。

修改验收器的载入路径时，补真实坏包负例。
在自有 allowlist 候选中，令业务模块导入时抛出固定异常。
保持包身份、静态归档合同和其他文件有效。
分别用全新 profile 实跑旧门和新门。
核对实际退出码及原始命令输出，不匹配日志尾部的预期说明。
新门须拒绝坏业务包，再接受最终正常归档。
坏包绝不安装到 live Desktop，不发布到任何渠道。

## 升级合同

- 分开 Config、Remote ABI、固定壳和业务 payload。
- 新增扩展不得改掉未变的截图合同。
- 基础实现可升级；用适配层保留旧调用合同，不删除安全校验。
- 无法兼容时保留旧可用版本，披露受影响的运行壳。
- 正常发布先消除阻塞；正式修复 tag 验证须另有本次明确授权。
- 用真实旧壳加载新 payload，不能只验新包首装。
- 每项新增业务功能都验同一官方 tag 升级路径。
- 升级后逐项核对入口、实际接口及业务动作，无需重启或切开关。
- 截图恢复不代表其他功能就绪；包内代码不代表运行时装配。
- 纯版本回复不代替新增能力验收；缺失的功能仍记为失败。
- 核对所有已发布壳；同路径的互斥合同不能靠改回旧值双兼容。
- 新业务接口随版本化实现注册官方能力面，不依赖旧壳刷新静态接口。
- 先等 Host 子 Fiber 就绪，再独立核能力版本；Client 方法存在不证明 Host 注册。
- 免重启必须绑定实际新后台及同进程操作结果。
- 版本递增、enable 和磁盘更新都不代替代码换载。

## 公开文档双语同步

维护 `README.md` 与 `README.en.md`。
维护 `PUBLISHING.md` 与 `PUBLISHING.en.md`。
功能、版本、安装或兼容边界变化时，双语成对同步。
两套入口互链；英文正文完整，不夹半份译文。
README 只写产品、用户动作和必要提醒。
不把页脚装饰或验收流水列为产品功能。
PUBLISHING 写渠道、技术合同与发布决定。
同步版本、平台、隐私边界、致谢与未验门。
历史合同原文保留原字节；英文链接原文归档。
第三方许可和私人用户原话不改写。

简介由现有 `metadata:sync` 同步两份 README。
该工具不翻译正文；主代理逐段核对事实。
运行 `metadata:check` 和 `tests/public-guides.test.ts`。
指南测试守护结构与边界，不证明译文准确。
检查全部跟踪文档的链接、L3 与模块地图。
保留历史版本语境，不把旧合同改成当前授权。
文档修改不授权重打 tag、安装或覆盖冻结归档。

## 收尾与交接

每项结果区分通过、失败、取消、未运行和未知。
源码、归档、隔离 Host 通过不等于全部完成。
新 blocker 须修复或纳入本次明确的修复验证范围。
已授权例外仍保留失败或未验状态，不把风险写成通过。
回执记命令、退出码、候选摘要、门的范围与下一步。
公开 README 写能力，PUBLISHING 写发布合同。
AGENTS 只写长期规则，不追加会话流水。
私人原话逐字保存，发布遵守 `private-docs-publish`。

清理前核对具体路径、owner、符号链接和活动进程。
只删除本任务已过期、自有且未被使用的临时产物。
保留未提交源码快照、坏包、红证据及必要复现材料。
取消或卸载须等待实际流、子进程和原生操作结算。
Abort 信号或立即返回不证明操作已停止。
子目录自有不代表共享父目录自有。
进程或所有权未知时保留，不杀未知进程。
