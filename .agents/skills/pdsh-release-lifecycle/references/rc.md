# RC 制作、测试与恢复

## 制作

读取 [pack-rc 契约](../../../../tools/pack-rc.ts)。
稳定树始终保留 `@daftai/pdsh` / `pdsh`。
不要先给正式源码改名，再靠备份恢复。

在已获候选构建授权后，执行 `pnpm bundle:rc <正整数编号>`。
只在自有 staging 派生 `@daftai/pdsh-rc` / `pdsh-rc`。
基础版本取正式 manifest，编号来自当前任务。
已有编号输出不得覆盖；保留回执与源码摘要。
不从另一个 RC 派生 RC，不复制 staging 生成物回源码树。
同一候选保留独立 Config、偏好和媒体仓。
RC 关闭稳定 updater，不向正式配置地址写入。
制作工具不安装到用户 profile，也不重启应用。

## 隔离 Host

读取 [verify-host 契约](../../../../verify-host.ts)。
RC 验证时显式指定本次 `candidateRoot`。
否则会把稳定源码身份或字节当作 RC 的比较依据。
被装 tgz、candidateRoot 和回执必须属于同一候选。
遵守入口对临时 profile、官方 PNPM 和空消费者的校验。
核对实际业务版本、八组合、revision 恢复与生命周期。
隔离 Host 通过后，Desktop 与原生门仍独立。

## 实机安装与测试

只有本次实机安装授权才进入以下步骤。
先记录稳定包身份、启用状态和 accepted 配置的脱敏证据。
通过官方插件管理器停用稳定包，不卸载它。
再安装并启用 RC，不让两个包同时启用。
Desktop 独占的操作不得改由外部 CLI 绕过。

替换包后回读官方结果及实际运行身份。
遵守 `restart-required`，保留未保存工作。
重启须有本次授权；无授权时停在待重启状态。
不能用反复 enable 冒充新代码换载。
固定壳、Config、Remote ABI 或依赖变化须正常加载。
同合同业务换载也须等旧操作结算。
首次 bootstrap 不证明旧版到新版的免重启升级。

没有确认身份的真实 UI 能力时，保留实机缺口。
不启用 Inspector、不为 CDP 重启应用，也不私建 IPC。
Host HTTP listener 不是 CDP endpoint。
不抢前台；原生点击会改变焦点，不能声称无干扰。

按根指南逐项验 UI、原生像素、持久化及取消。
暖切换须比较选中环、accepted 状态与预览/导出。
不能以本地库存不重读，推断显示一定正确。
初拍、重拍和撤权分别观察真实结果。
失败不改成未运行，也不让旧候选覆盖新失败。

## 恢复

测试结束后，通过官方管理器只卸载 RC。
再重新启用保留的稳定包。
等待旧操作结算，回读实际稳定运行身份。
核对 Config、入口、功能与既有用户数据仍在。
禁止整份旧配置覆盖新 revision。
不清空稳定或 RC 媒体仓来伪造干净恢复。

恢复未观察、失败或仍待重启时，明确保留缺口。
“准备恢复”不是已恢复，“磁盘仍在”不是已加载。
实机测试授权不自动包含公开 main、tag 或 Release。
若用户继续要求正式发版，另读稳定流程。
