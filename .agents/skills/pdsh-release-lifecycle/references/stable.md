# 稳定发布与远端闭环

## 发布范围

核对本次明确授权的版本、渠道与已披露未验门。
例外只覆盖用户本次明确接受的缺口。
失败仍标为失败，未验仍标为未验。
新代码 blocker 不归入旧例外。
用户明确授权正式修复 tag 验证时，记录目标与已知限制。
按该 tag 实跑官方 Git 升级；本地归档测试不能替代它。
逐项核对该版新增功能的入口、实际接口和业务动作。
保持同进程，不重启或切开关补齐业务功能。
只有基础功能恢复时，整体升级仍未完成。
逐版验证不等于递增版本号就能修复旧壳。
同意私人文档发布不等于同意公开代码发布。
公开发布不等于 live Desktop 安装或重启授权。
GitHub Release 默认关闭。
“发版”只授权 main 与稳定 tag。
只有另行明确授权才创建 GitHub Release。
npm 保持关闭。
默认不创建 Release 页面或上传附件。
更新入口只读 tags API，再安装固定 SHA。
main 提交或 Release 页面不能替代稳定 tag。

RC 通过不意味着正式归档通过。
在稳定源码中提交同源功能，不反向复制 RC staging。
只手改 `package.json.version`，再用官方生成流程重建。
声明、Typert 面、版本化业务与原生助手须同源。
RC 的临时身份、元数据和运行产物不得混入正式包。

## 冻结最终安装件

先检查锁定依赖、文档和公开元信息。
运行 `pnpm test` 与 `pnpm run bundle`。
两者已有构建步骤，不靠旧 `lib/` 或助手填门。
核对真实 tgz 的 allowlist、字节、唯一版本与 helper 0755。
Mac universal 与 Windows x64/asInvoker 分别核对。
所有打包命令成功后再记录最终归档摘要。
后续重建改变字节时，重做受影响的安装件门。

在全新自有 profile 运行现有 `verify-host.ts`。
绑定最终归档、精确宿主和官方 PNPM。
须通过实际首次载入及重新启用的版本核对。
业务模块静态合法却导入失败时，不得发版。
安装结果、文件摘要与 service 注册不能代替实际导入。
按任务完成 Desktop、原生和恢复门，或明确记录授权例外。

## 提交、合并与 tag

再次核对 HEAD、全部未提交路径和远端 main。
只暂存本任务明确路径，并逐项检查 staged diff。
不 stash、reset、clean、强推或覆盖他人 WIP。
提交完整源码、文档和生成物，不提交 output 或私人证据。
只有工作树干净后，才切换到 main 并合并任务提交。
远端前进或产生冲突时，重新审查后再验，不循环抢推。

共享脏树含他人 WIP 时，不挪用或隐藏它来凑清洁树。
可在本次发布授权内，建立自有临时干净 clone。
只带入已审查的本任务提交，不复制整个脏树。
基于已核远端 main，重验产物、归档和发布 HEAD。
无法完整隔离时停止公开发布，保留原工作树。

在清洁 main 执行 `pnpm release:check`。
元信息的网络或鉴权失败就是门失败，不跳过。
核对用户 hooks 与 `core.hooksPath`，不覆盖已有 hooks。
本地 hook 不是服务器强制策略，也不授予发布权限。

`v<version>` 必须指向已验 main HEAD。
已有同名 tag 指向其他提交时停止，不移动或删除它。
普通推送 main 与该 tag，可用远端支持的 atomic push。
不要使用 `--force`、`--no-verify` 或移动旧 tag。
推送结果未知时先读回 refs，不盲目重发。

## 远端闭环

远端回读 main、tag 及实际提交 SHA。
从生产使用的 tags API 核对版本与 commit.sha。
核对 updater 会选中该稳定版本及固定 SHA。
这个只读结果不证明实际 Desktop 升级完成。
检查本次 SHA 的 CI；未触发就是未触发，不写成功。
最后回读本地 status 与远端 refs，再报告已发布。

仅当用户另行点名创建 GitHub Release，才建立页面。
附件只上传已验归档，并下载回读摘要。
结果未知时先读回，不盲目重复创建或上传。
误建页面时只撤销自有页面与附件，不删除稳定 tag。

原话、命令结果和例外回执发布到私人证据仓。
私人发布须获取 owner lock，只提交本任务文件。
并发规则、重试和清理由 `private-docs-publish` 规定。
公开指南不收录私人日志、用户路径、账号或像素。
发版结束仍保留实机未验项，不声称安装包已更新。
